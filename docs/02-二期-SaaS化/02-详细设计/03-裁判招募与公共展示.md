# 裁判招募与公共展示设计

> 状态：已确认业务规则，待实施级页面与接口评审  
> 对应决策：`SaaS-ADR-011`、`SaaS-ADR-012`、`SaaS-ADR-013`  
> 适用范围：Judge H5 招募、主办方筛选、裁判资料范围、公共赛事和结果展示。

## 1. 设计目标

一期已有统一的 `judge_account`、Judge H5 登录和跨比赛评审任务能力。二期在此基础上新增“先申请、再录用、后分桌”的链路，不改变现有扫码、评分、桌长确认和排序流程。

```text
主办方发布裁判招募
→ 裁判在 Judge H5 申请并提交可参加场次
→ 主办方筛选申请人
→ 录用 / 候补 / 不录用
→ 主办方在既有评审编排中安排桌次、角色和任务
→ 裁判在 H5 完成现场评审
```

招募申请、主办方录用和正式评审分配是三个不同业务对象，不能把“已申请”直接视为已有评审权限。

## 2. 招募配置与状态

每场比赛最多配置一条当前有效的裁判招募，可包含多个日期或场次。

| 配置项 | 说明 |
| --- | --- |
| 是否开放招募 | 控制是否出现在 Judge H5 和公共页面 |
| 招募开始/截止时间 | 控制申请窗口 |
| 比赛日期、工作时间、地点 | 裁判判断是否可参加 |
| 赛事介绍与裁判要求 | 向裁判公开的招募说明 |
| 可参加场次 | 由主办方定义的日期/时段选项 |
| 预计需求 | 可选，供裁判了解规模，不等同正式分桌人数 |

建议状态：

```text
DRAFT → OPEN → CLOSED → ARCHIVED
```

招募关闭后不能再提交新申请；已提交申请仍可由主办方继续处理。

## 3. 裁判申请与处理

### 3.1 Judge H5

裁判登录后可以查看开放招募的赛事。列表至少展示比赛名称、实际主办方、日期、地点、时间、招募截止时间和要求摘要。

提交申请时，裁判选择可参加的日期或场次，可填写补充说明。每名裁判对同一招募只能保留一份当前申请；在招募关闭前允许修改可参加场次。

申请状态：

| 状态 | 含义 |
| --- | --- |
| `APPLIED` | 已提交，等待主办方处理 |
| `SHORTLISTED` | 主办方候补或待进一步确认 |
| `ACCEPTED` | 已被录用，可等待正式分桌 |
| `REJECTED` | 本次未录用 |
| `WITHDRAWN` | 裁判撤回申请 |

### 3.2 主办方后台

主办方管理员只可查询自己赛事的申请人，可按申请状态、可参加场次、资质关键词和利益冲突提示筛选。

主办方可将申请人设为录用、候补或不录用，并写入内部处理备注。录用不自动创建评审桌成员；主办方仍需在既有评审编排界面明确选择桌次和角色。

## 4. 裁判资料可见范围

| 查看者 | 可见范围 |
| --- | --- |
| 平台超级管理员 | 完整裁判资源库及审核信息，按隐私规则处理 |
| 平台赛事管理员 | 平台自办赛事所需裁判及其申请、分配信息 |
| 主办方管理员 | 仅本组织赛事的申请人；展示办赛筛选所需资料 |
| 其他主办方 | 不可查看 |

主办方侧默认展示姓名、资质、申请场次、利益冲突说明和申请备注。手机号、微信号等联系方式应由产品确认何时显示；实现时必须通过 `PiiService` 解密，避免在列表日志、导出或前端缓存中泄露明文。

评审评分界面维持一期匿名边界：裁判不因招募或组织信息而获得厂牌、酒名、联系人、报名付款或主办方内部信息。

## 5. 与既有评审编排的关系

当前系统已经通过比赛基础评审桌、评审分配、轮次桌和桌成员表达正式评审任务。二期应保持其职责：

| 业务环节 | 二期数据来源 | 是否获得评分权限 |
| --- | --- | --- |
| 提交招募申请 | 招募申请 | 否 |
| 主办方录用 | 申请处理结果 | 否 |
| 指定基础桌和角色 | 既有 `competition_judge_assignment` | 视轮次发布而定 |
| 创建轮次桌成员 | 既有 `round_table_member` | 轮次发布后获得任务 |

正式分配时建议记录来源申请 ID，便于追溯录用与实际安排的关系；但不能让来源字段替代对现有评审分配和轮次状态的校验。

## 6. 公共展示

平台公共页面统一展示：

- 正在报名的赛事；
- 正在招募裁判的赛事；
- 已发布结果的赛事。

第三方赛事必须在赛事详情、招募页、结果页和列表卡片明确显示：

```text
主办方：实际主办方名称
```

可选展示主办方 Logo。公开页面不得把第三方赛事误导为全部由啤酒事务局直接主办。

## 7. 验收重点

- 未登录裁判不能提交申请；不符合评审账号状态的裁判不能申请。
- 裁判只能申请 `OPEN` 且未过截止时间的招募。
- 主办方 A 无法查看主办方 B 的申请人、联系方式或处理记录。
- 录用裁判在未进入正式分桌前，不应看见或访问评审任务。
- 裁判可在同一账号中查看多个比赛的招募申请和正式任务，互不混淆。
- 公共赛事、招募和结果页面均正确展示实际主办方。
