# 二期 SaaS 化决策记录

> 状态：持续维护  
> 用途：记录会影响多个模块、后续难以低成本撤销的重要决定。

## 使用方式

- 每项决定使用唯一编号，例如 `SaaS-ADR-001`。
- 只记录已经讨论并形成结论的事项。
- 方案发生变化时保留原记录，追加新的决定及替代关系。
- 详细分析可以放入 `02-详细设计/`，本文件保留结论和影响范围。

## 记录模板

### SaaS-ADR-XXX：决策标题

| 项目 | 内容 |
| --- | --- |
| 状态 | 提议中 / 已确认 / 已废弃 / 已替代 |
| 日期 | YYYY-MM-DD |
| 背景 | 为什么需要作出决定 |
| 备选方案 | 评估过的主要选择 |
| 决定 | 最终采用的方案 |
| 影响 | 涉及的模块、数据和实施工作 |
| 关联文档 | 总体方案或详细设计路径 |

## 已确认决策

### SaaS-ADR-001：保留平台自办与租户 SaaS 两种赛事运行模式

| 项目 | 内容 |
| --- | --- |
| 状态 | 已确认 |
| 日期 | 2026-07-27 |
| 背景 | 一期已服务啤酒事务局自办赛事；二期需要向第三方主办方提供 SaaS 服务。 |
| 决定 | 共用一套赛事核心能力。平台组织创建的平台自办赛事延续一期支付与流程，免啤酒币；第三方主办方创建的赛事采用租户收款和啤酒币规则。 |
| 影响 | 组织模型、比赛归属、鉴权、支付、退款、公开展示和测试均需区分两种模式。 |
| 关联文档 | `01-总体方案.md`、`02-详细设计/01-组织、权限与数据隔离.md` |

### SaaS-ADR-002：第三方主办方由平台后台开通

| 项目 | 内容 |
| --- | --- |
| 状态 | 已确认 |
| 日期 | 2026-07-27 |
| 背景 | 初期主办方数量少于 5 家，均为已知合作方。 |
| 备选方案 | 自助注册审核；后台创建并分发账号；同时支持两种方式。 |

### SaaS-ADR-003：后台使用三类操作身份

| 项目 | 内容 |
| --- | --- |
| 状态 | 已确认 |
| 日期 | 2026-07-27 |
| 决定 | 使用平台超级管理员、平台赛事管理员、主办方管理员三类身份。同一主办方下管理员权限一致，不在二期区分负责人和工作人员。 |

### SaaS-ADR-009：啤酒币支持在线购买并自动到账

| 项目 | 内容 |
| --- | --- |
| 状态 | 已确认 |
| 日期 | 2026-07-27 |
| 备选方案 | 后台手工充值；申请后审核充值；在线购买自动到账。 |
| 决定 | 租户在线购买啤酒币，支付成功后自动创建充值批次和余额流水。平台保留严格审计的人工更正能力。 |
| 影响 | 需要啤酒币商品、购买订单、微信支付回调幂等处理、充值批次、余额流水和批次扣减分摊。 |

### SaaS-ADR-010：啤酒币按通用企业账户设计，未来供酒款评测平台复用

| 项目 | 内容 |
| --- | --- |
| 状态 | 已确认 |
| 日期 | 2026-07-27 |
| 背景 | 酒款评测平台尚未开发，但未来需要与赛事 SaaS 共用企业账户和啤酒币余额。 |
| 决定 | 二期不对接外部系统；钱包、充值批次和流水归属通用企业账户，不使用“赛事余额”命名或专属模型。未来酒款评测平台复用同一钱包。 |
| 影响 | 企业账户与赛事主办方组织需可关联，但不能把钱包模型绑定到比赛表或赛事专用表。 |
| 关联文档 | `02-详细设计/02-租户收款与啤酒币.md`、`02-详细设计/04-数据库迁移设计.md` |
