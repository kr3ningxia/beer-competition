# 啤酒事务局赛事平台 SaaS化 业务需求说明

## 1\. 业务背景

啤酒事务局已经开发了一套赛事管理平台，目前主要服务于啤酒事务局自己组织的比赛。现有平台已经具备参赛报名、报名费支付、酒款信息管理、匿名编码、裁判扫码评分、评审分组、数据汇总和结果查询等主要功能。

现在希望将现有平台升级为一套支持第三方赛事主办方使用的 SaaS 产品。经过啤酒事务局审核的赛事主办方，可以在平台上独立创建和运营自己的比赛，并使用现有的报名、评审和结果管理能力。

本次改造的核心，是让同一套赛事平台能够同时服务多个彼此独立的赛事主办方，而不是重新开发一套比赛系统。同时，平台引入“啤酒币”作为第三方主办方使用赛事发布及评审管理能力的统一计费工具\.

## 2\. 改造目标

1. 第三方赛事主办方可以自主申请入驻平台。

2. 啤酒事务局可以审核并决定是否开通主办方权限。

3. 审核通过的主办方可以自主创建、发布和管理比赛。

4. 每个主办方可以添加自己的管理员，共同运营比赛。

5. 不同主办方的数据和权限必须相互隔离。

6. 参赛者可以使用同一个平台账号参加不同主办方的比赛。

7. 裁判可以使用同一个裁判账号报名参加不同比赛的评审。

8. 平台建立可供各比赛共同使用的啤酒风格库和裁判资源库。

9. 第三方比赛及其公开结果统一展示在啤酒事务局赛事平台上。

10. 企业用户可以使用统一账户及啤酒币余额，按赛事实际参赛酒款数量购买和使用平台服务。

11. 各主办方自行收取和处理本比赛的报名费，平台不参与报名费分账和资金结算。

## 3\. 主要用户角色

### 3\.1 啤酒事务局管理员

- 平台管理员

    - 审核第三方赛事主办方的入驻申请并开通权限。

    - 管理平台公共啤酒风格库和裁判资源库。

    - 管理企业账户的啤酒币充值、余额调整、有效期及消费流水。

    - 查看和管理平台内的主办方及比赛。

    - 在出现违规、争议或异常情况时进行必要干预。

- 啤酒事务局赛事管理员

    - 管理啤酒事务局主办的赛事，无权限查看第三方赛事的非公开信息。

### 3\.2 第三方赛事主办方

- 创建、发布和管理本组织的比赛。

- 添加本组织的其他管理员或工作人员。

- 查看本企业账户的啤酒币余额、有效期及消费记录，并根据办赛需要充值。

- 管理本组织比赛的报名、收款信息、酒款、裁判、评审和结果。

- 只能查看本组织创建的比赛及相关数据，不能查看其他主办方的数据。

### 3\.3 参赛者或参赛厂牌

- 使用现有参赛者端报名不同主办方发起的比赛。

- 提交酒款资料、按照主办方提供的方式支付报名费、查看报名状态和评审结果。

- 同一个账号可以参加多场比赛，无需重复注册。

### 3\.4 裁判

- 使用统一的裁判账号维护个人资料和裁判资质。

- 浏览平台上正在开放裁判招募的比赛。

- 根据比赛日期和工作时间，报名参加感兴趣且有时间参加的比赛。

- 被主办方录用和分组后，使用现有评审端完成评分。

## 4\. 核心业务需求

### 4\.1 主办方入驻与审核

第三方赛事主办方可以自主注册企业账户，并提交必要的组织资料和联系人信息。啤酒事务局在平台后台审核申请，通过后为其开通赛事主办方权限；未通过时，主办方可以根据审核意见补充或修改资料。

第三方主办方并非注册后即可直接办赛，必须先经过啤酒事务局审核。

同一企业账户可同时使用赛事平台和酒款评测平台。企业主体资料、登录账户和啤酒币账户可以共用，无需为两项业务重复注册和充值，但两个平台按照各自的业务规则消耗啤酒币。

### 4\.2 主办方团队与权限隔离

主办方负责人可以在企业账户下添加多名管理员或工作人员，共同管理赛事。具体的成员角色和权限范围由产品经理进一步规划。

无论主办方添加多少名成员，所有成员都只能查看和管理本组织的比赛数据，不能进入其他主办方的后台，也不能查看其他比赛的报名、付款、裁判或评分信息。

啤酒事务局作为平台方，可以查看和管理全平台信息。

### 4\.3 企业账户与啤酒币

啤酒币是企业用户使用啤酒事务局赛事平台及酒款评测平台相关服务的统一虚拟计费单位。企业用户可以在账户中查看啤酒币的可用余额、即将到期数量、充值记录和消费记录。

企业用户通过微信号 `beerxms` 联系啤酒事务局小秘书，咨询价格并按实际需要购买啤酒币。啤酒币由啤酒事务局管理员充值至相应企业账户，自购买并到账之日起1年内有效，不允许退款或转让。

同一企业账户的啤酒币余额可以在赛事平台和酒款评测平台中使用，但两项业务的计费标准不同：

- 赛事平台：1枚啤酒币对应最多10款\*参赛酒的赛事评审管理服务，每场比赛至少消耗1枚。

- 酒款评测平台：继续按照该平台另行确定的计费规则消耗啤酒币。

如账户中存在不同到期日的多批啤酒币，系统应优先消耗最早到期的啤酒币，减少企业用户因到期造成的损失。

### 4\.4 比赛创建、发布与首次扣币

审核通过的主办方可以在后台自主创建比赛，填写和配置比赛名称、介绍、报名时间、比赛日期、地点、参赛规则、送样要求、报名费用、收款方式、比赛组别、评分方式、奖项设置及结果发布时间等内容。

该后台应尽量复用现有啤酒事务局主办方后台的功能和操作逻辑。在现有功能基础上，增加主办方归属、权限隔离、啤酒币计费和第三方比赛发布能力。

主办方可以保存和预览尚未发布的比赛草稿。正式发布比赛时，企业账户中必须至少有1枚可用啤酒币；系统在发布成功时立即扣除1枚。余额不足时不得发布。

每场比赛至少消耗1枚啤酒币。即使最终参赛酒款不足10款或没有形成有效报名，发布时已经扣除的1枚仍作为该场比赛的最低平台使用费用。

比赛发布后，应显示在啤酒事务局赛事平台上，参赛者可以进入比赛详情页完成报名。

### 4\.5 报名截止后的啤酒币核算与评审权限

报名截止后，平台根据本场比赛实际有效的参赛酒款数量核算最终应消耗的啤酒币。计费数量以10款为一个单位，不足10款按10款计算，即向上取整：

> 最终应消耗啤酒币 = max（1，向上取整〔实际有效参赛酒款数 ÷ 10〕）

“实际有效参赛酒款”是指报名截止并准备进入评审分组时，仍处于有效报名状态、未被主办方取消的酒款。由于平台不统一追踪各主办方的报名费到账情况，是否属于有效报名由主办方在锁定报名数据前确认。

发布比赛时已经扣除的1枚计入整场比赛最终应消耗的啤酒币，不重复收费。报名截止后，系统仅计算并扣除尚需补足的差额：

> 进入分组时需补扣啤酒币 = 最终应消耗啤酒币 − 发布时已扣除的1枚

例如，一场比赛最终有35款有效参赛酒，应按40款计算，整场比赛共消耗4枚啤酒币。发布时已经扣除1枚，进入评审分组时还需再扣除3枚。

系统应在报名期间持续显示当前报名酒款数量、预计总消耗和预计还需补足的啤酒币数量，方便主办方及时充值。

主办方开始进行正式评审分组和组别分配前，企业账户必须有足够余额支付差额。余额不足时，系统应提示主办方联系啤酒事务局小秘书充值，并暂时锁定以下功能：

- 确认和锁定评审酒款名单；

- 进行酒款分组及组别分配；

- 生成正式匿名编码或评审二维码；

- 安排裁判的具体评审任务。

主办方确认进入分组阶段时，系统自动扣除应补差额，并记录赛事名称、有效酒款数、计费档位和扣币数量。扣币成功后，参赛酒款数量和计费基数进入锁定状态，主办方方可继续完成分组和评审安排。

锁定后如确需新增参赛酒款，系统应重新计算总量；如新增酒款使计费档位上升，主办方须先补扣相应啤酒币后才能为新增酒款分组。锁定后删除或取消酒款，已消耗的啤酒币原则上不自动退回，特殊情况由啤酒事务局后台处理。

### 4\.6 公共啤酒风格库与赛事分组

平台需要建立一套由啤酒事务局统一维护的公共啤酒风格库，供不同赛事共同使用。

主办方在创建比赛时，可以引用公共风格库，也可以根据本场比赛的规则创建自己的赛事分组。

主办方创建自己的比赛分组，不应直接修改平台公共风格库。

主办方只有在完成本场比赛应付啤酒币的补扣后，才能正式进行酒款分组和组别分配。

### 4\.7 参赛报名、收款方式与酒款管理

第三方比赛继续使用现有参赛者端的主要能力。第三方主办方可以在自己的后台查看和管理本比赛的报名信息、酒款资料、匿名编码和入库状态，并进行取消报名、数据导出等操作。整体逻辑与啤酒事务局目前使用的后台基本一致。

每个主办方可以设置自己比赛的报名费用，并配置本场比赛适用的收款方式。收款主体是实际赛事主办方，报名费直接进入主办方自己的收款账户，不进入啤酒事务局的平台账户。

收款方式按照以下优先级设计：

1. ~~优先支持主办方绑定自己的微信支付或支付宝收款账户。技术条件允许时，参赛者支付后系统自动更新付款状态，但资金仍直接进入主办方账户。~~

2. 如暂时无法完成微信支付或支付宝账户接入，允许主办方上传普通收款二维码，个人或企业收款码均可。

3. 同时支持主办方填写银行账户名称、账号、开户行等收款信息，供参赛者线下转账。

使用普通收款二维码或银行转账时，收款确认由主办方自行完成。平台可以保留供主办方手动标记付款状态的功能，但不负责核对到账金额，也不承担财务对账责任。

平台不再按照报名费金额收取固定比例的平台服务费，也不参与报名费的代收、分账、结算、催收、坏账处理或原路退款。参赛者取消报名、主办方同意退款等情况下，相关款项由主办方和参赛者直接处理；平台只根据主办方操作同步更新报名状态。

### 4\.8 裁判资源库

平台需要建立统一的裁判资源库。每名裁判拥有一个可跨比赛使用的账号，并可以维护自己的基本资料、裁判资质和评审经历。

不同赛事主办方可以从报名本比赛的裁判中进行筛选，但裁判资料的可见范围需要受到平台规则和个人信息授权的限制。

### 4\.9 裁判招募与双向选择

主办方创建比赛时，可以选择开放裁判招募，并发布相应的招募信息。

裁判登录后，可以看到目前所有开放招募的比赛，以及比赛日期、工作时间、地点、赛事介绍、裁判要求和其他必要信息。裁判可以选择自己感兴趣且有时间参加的比赛，并勾选可以参加的具体日期或场次后提交申请。

主办方可以在后台查看报名本比赛的裁判，根据其资料、资质和可参加时间进行筛选，并决定录用、候补或不录用。

主办方录用裁判后，再为其安排具体的评审日期、评审桌、评审角色和评审任务。因此，裁判申请、主办方录用和正式评审分组是三个不同环节。

### 4\.10 比赛评审

主办方完成啤酒币补扣和裁判筛选后，可以继续使用现有后台进行裁判分组和评审安排。比赛期间，裁判继续使用现有评审端完成扫码、匿名评分和评语填写，桌长继续完成评分汇总。

SaaS 化后需要保证：

- 裁判能够在同一个账号中看到自己参加的不同比赛。

- 裁判只能进入已经被录用并分配任务的比赛。

- 每场比赛可以使用自己的分组、评分表和评审安排。

- 不同比赛的酒款、二维码、评分和结果不能互相混淆。

- 主办方只能查看自己比赛的评审过程和结果。

### 4\.11 结果发布与平台展示

评审结束后，主办方可以使用现有结果管理功能确认并发布比赛结果。

结果发布后：

- 参赛者可以查看自己的评分、评语和获奖情况。

- 第三方比赛的公开结果显示在啤酒事务局赛事平台上。

- 公开页面需要明确标注比赛名称和实际赛事主办方，避免被误解为全部由啤酒事务局直接主办。

平台可以统一展示正在报名的比赛、正在招募裁判的比赛和已经发布结果的比赛。

## 5\. 核心业务流程

### 5\.1 主办方办赛流程

主办方注册企业账户 → 提交资料 → 啤酒事务局审核 → 获得主办方权限 → 直接点击购买或联系小秘书购买啤酒币 → 创建比赛草稿 → 发布比赛并扣除1枚啤酒币 → 管理报名及自行收款 → 报名截止后确认有效酒款数量 → 补足啤酒币余额 → 进入分组并自动扣除差额 → 招募及安排裁判 → 组织评审 → 发布结果。

### 5\.2 参赛者流程

登录平台 → 选择比赛 → 提交酒款 → 按照主办方提供的方式支付报名费 → 查看报名和入库状态 → 比赛结束后查看反馈和结果。

### 5\.3 裁判流程

登录裁判账号 → 浏览开放招募的比赛 → 选择可参加的日期并报名 → 等待主办方筛选 → 确认参加 → 接受分组和任务 → 完成现场评审。

### 5\.4 啤酒币计费流程

企业充值 → 发布比赛扣除1枚 → 报名期间实时显示预计用量 → 报名截止后确认有效酒款数 → 按每10款向上取整核算总量 → 检查账户余额 → 余额不足则暂停分组并提示充值 → 主办方确认进入分组 → 自动扣除差额并生成消费记录。

## 6\. 关键业务规则汇总

|事项|业务规则|
|---|---|
|账户关系|赛事平台与酒款评测平台可以共用同一企业账户及啤酒币余额|
|充值方式|直接点击购买，或通过微信号 `beerxms` 联系啤酒事务局小秘书咨询购买，由后台充值|
|有效期|每批啤酒币自购买并到账之日起1年有效|
|退款与转让|啤酒币不允许退款或转让|
|最低消费|每发布一场比赛至少消耗1枚啤酒币|
|赛事计费单位|1枚啤酒币对应最多10款参赛酒，不足10款按10款计算|
|发布扣币|正式发布比赛时立即扣除1枚，余额不足不能发布|
|最终核算|报名截止后按实际有效参赛酒款数向上取整，计算整场比赛应消耗总量|
|分组扣币|进入正式分组时扣除最终总量与已扣1枚之间的差额；余额不足不得分组|
|计费锁定|分组扣币成功后锁定计费基数；新增酒款可能触发补扣，删减酒款原则上不自动退币|
|报名费收款|报名费直接进入主办方的微信、支付宝或银行账户|
|备用收款方式|可展示个人或企业普通收款二维码，也可展示银行账户信息|
|平台资金责任|平台不代收、分账、结算或追踪报名费|
