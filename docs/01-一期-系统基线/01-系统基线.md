# 一期系统基线

> 状态：已完成、冻结基线  
> 基线日期：2026-07-27  
> 用途：为后续开发提供简洁、稳定的现有系统上下文。

## 1. 系统定位

一期是面向啤酒赛事主办方、参赛厂商和评审人员的比赛管理系统，覆盖赛事配置、报名缴费、送样入库、现场评审、轮次晋级、奖项确认和结果发布。

当前数据模型没有租户或组织域。比赛 `competition` 是业务配置和现场流程的主要范围边界，后台管理员共享同一套管理空间。二期 SaaS 化产生的新模型和新规则统一记录在 `docs/02-二期-SaaS化/`，不反向修改本文件描述的一期事实。

## 2. 工程组成

| 工程 | 技术基线 | 职责 |
| --- | --- | --- |
| `beer-competition-api` | Java 17、Spring Boot 3.5.6、MyBatis-Plus、MySQL、Redis、JWT | 后台、厂商端、评审端接口及核心业务 |
| `beer-competition-console` | Vue 3.5、Element Plus、Vite 7 | 厂商 Portal 和主办方后台 |
| `beer-competition-judge-h5` | Vue 3.5、Vite 7 | 手机端评审、扫码评分、桌长汇总和排序确认 |
| `docs` | Markdown、SQL | 当前基线、二期设计、工程约定和运维资料 |

后端为单体应用，三端共用同一后端服务和 MySQL 数据库。远程部署方式见 `docs/04-运维/啤酒大赛系统部署与运维速查.md`。

## 3. 使用角色

| 角色 | 使用端 | 核心职责 |
| --- | --- | --- |
| 主办方管理员 | Console 后台 | 赛事配置、报名管理、收样、评审编排、轮次管理、奖项和发布 |
| 厂商联系人 | Console Portal | 查看赛事、批量或单款报名、支付、下载标签、提交送样、查看结果 |
| 普通评审 | Judge H5 | 查看任务、扫码、独立评分、确认桌长结果 |
| 桌长 | Judge H5 | 个人评分、第一轮汇总、晋级选择、后续轮正式排序 |

评审角色与具体比赛、轮次和评审桌关联，同一评审可在不同比赛中承担不同角色。

## 4. 一期核心业务链路

```text
赛事配置
→ 开放报名
→ 厂商提交一款或多款酒
→ 微信支付、银行转账或测试环境模拟支付
→ 下载匿名参赛标签并提交送样信息
→ 主办方确认收样和入库
→ 创建并发布第一轮
→ 评审独立评分
→ 桌长填写共识结果并选择晋级
→ 同桌确认，主办方锁定轮次
→ 创建后续排序轮
→ 生成并确认奖项
→ 发布结果和证书
```

完整业务规则以 `02-业务流程与规则.md` 为准。

## 5. 已落地能力范围

### 5.1 厂商 Portal

- 公开赛事、赛事详情和公开结果。
- 手机号验证码登录、厂商资料维护和头像上传。
- 单款及多酒款批量报名、动态报名字段和费用试算。
- 微信 Native/JSAPI 支付、银行转账凭证提交、测试环境模拟支付。
- 支付状态查询、退款申请和相关状态展示。
- 参赛标签 PDF/PNG 下载、送样信息提交和参赛状态追踪。
- 个人评分结果、轮次结果、奖项和证书查看。

### 5.2 评审 H5

- 评审注册、登录、资料完善、审核状态和比赛任务。
- 二维码、标签编码和短编号解析。
- 按比赛及角色加载评分表，提交和修改个人评分。
- 桌长共识分、综合评语、晋级选择和同桌确认。
- 后续轮参考排序、正式排序及排序确认。

### 5.3 主办方后台

- 后台账号、赛事、组别、风格库、报名字段、评分表和评审桌管理。
- 报名酒款、付款、银行转账、退款、送样、入库和删除影响管理。
- 评审审核、比赛编排、第一轮及后续轮管理。
- 评分进度、现场看板、反馈审查和赛事分析。
- 标签、报名、送样和评分数据导出。
- 奖项生成、确认、证书管理和结果发布。
- 关键后台操作日志。

## 7. 开发时必须保留的业务边界

- 评审端保持匿名，不展示酒名、厂商、联系人等可识别信息。
- 厂商只能访问自己提交的酒款、付款、结果和证书。
- 个人评分、桌长结果、同桌确认和轮次锁定存在明确的修改边界。
- 后续轮排序和奖项确认不能简单使用跨桌原始分数替代。
- 手机号和微信号等隐私字段遵循后端 `PiiService` 的加密、哈希和解密规则。
- 中文数据库写入必须使用 UTF-8/utf8mb4，并在写入测试数据后抽查字段十六进制值。
- 线上数据库结构目前通过 `docs/sql/` 中的脚本人工升级，执行前必须备份并验证。
