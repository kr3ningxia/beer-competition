# 啤酒大赛系统文档索引

> 当前阶段：一期系统已完成，二期进入 SaaS 化设计阶段。  
> 一期基线日期：2026-07-27。

本文档用于说明项目文档的阅读顺序、有效范围和存放规则。开发任务开始前，应根据任务范围读取对应文档，避免把历史需求、旧待办或部署信息混入当前设计上下文。

## 推荐阅读顺序

1. 阅读仓库根目录 `AGENTS.md`，了解开发、数据库和验收约束。
2. 阅读 `01-一期-系统基线/01-系统基线.md`，了解当前代码承载的系统能力和模块边界。
3. 涉及比赛业务规则时，阅读 `01-一期-系统基线/02-业务流程与规则.md`。
4. 涉及二期 SaaS 化时，再读取 `02-二期-SaaS化/` 下对应文档。
5. 涉及后端结构或远程环境时，按需读取工程约定和运维文档。

## 目录说明

| 目录 | 用途 | 默认是否作为当前依据 |
| --- | --- | --- |
| `01-一期-系统基线/` | 一期已落地系统的稳定能力、业务流程和边界 | 是 |
| `02-二期-SaaS化/` | 二期总体方案、详细设计、实施计划和决策记录 | 是，按任务读取 |
| `03-工程约定/` | 代码组织和工程实现约定 | 是，开发时读取 |
| `04-运维/` | 部署、发布、数据库同步和故障排查 | 按需读取 |
| `二期临时文档/` | 二期需求原始材料与讨论草稿 | 否，仅用于追溯需求来源；已确认结论以 `02-二期-SaaS化/` 为准 |
| `99-归档/` | 历史需求和已被替代的文档 | 否，仅用于追溯 |

## 文档使用规则

- 一期文档记录已经落地的基线，不继续承载二期方案。
- 二期设计统一写入 `02-二期-SaaS化/`，不得直接覆盖一期业务基线。
- 同一主题只保留一份当前有效文档；旧版本移入 `99-归档/`。
- 历史文档中的“待开发”“待确认”和测试账号不代表当前状态。
- 当前实现与文档出现冲突时，应同时核对代码、数据库结构和最近的变更脚本，再修正文档。
- `02-二期-SaaS化/02-详细设计/` 存放已经确认、可供开发直接引用的二期主题设计；开始编码前按任务范围读取。
